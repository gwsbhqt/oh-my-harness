# 使用 remote-host

工作必须发生在明确选中的 SSH 目标上时，使用 remote-host，例如查看系统、执行脚本、传目录，或管理长时间任务。它的命令行和异步 Python 接口共用系统 SSH 传输。当关键证据是目标命令结果或传输后的内容时，这个工具很适合。

## 选择并检查目标

调用端支持 macOS，需要 Python 3.10 或更新版本及系统 SSH 工具。认证、端口、跳板和相关连接设置来自你的 SSH 配置。工具不内置机器清单。

```sh
remote-host hosts
```

机器列表使用原生输出，没有 JSON 模式。主动选择已配置别名。下面的虚构例子中，`example-target` 代表你已配置的别名：

```python
result = await skills.remote_host.run(
    "uname -a", host="example-target", quiet=True
)
```

检查 `result.code`、`result.out` 和 `result.err`。退出码为零只证明这条命令成功，不证明目标上的后续操作。机器固定设置可以保留默认目标、解释器和工作目录，但每个工具独立保存选机结果。这里选中目标，不会替 browser-use 或 computer-use 选目标。

## 选择合适的执行方式

有明确结束点的命令使用普通执行。脚本内容通过标准输入发送，不会交给本地 shell 展开。任务依赖解释器或工作目录时，通过文档接口明确选择它们。

较长的工作使用任务接口，启动、列出、跟随、等待或停止一个有名字的远程任务。保留任务身份，收取最终退出状态和输出。启动回执只表示已经启动，不是完成报告。有意在多次调用间保留 shell 状态的流程，可以使用持久会话。

以虚构的目录交接为例，复制到预期目标后，要核对最终目录树。复制接口默认验证。完整验证和清单可以比较内容，并记录目录与链接。快速验证只比较大小，证据更弱。除了传输成功，还要确认结果文件能用于目标任务。

## 处理不确定性和限制

写操作超时或连接断开时，远程结果可能未知。重试前检查目标或已记录任务。Python 结果通过 `remote_unknown` 和 `outcome` 表达这个区别。停止本地连接不能证明远程工作已停止。

Unix 目标需要具备所选操作要求的解释器和工具。Windows SSH 支持仅限明确的 PowerShell 脚本执行，不提供 Windows 桌面或浏览器控制。原生应用与浏览器功能还要求目标上有对应工具。缺命令会报错，不会退回本机或自动安装。

脚本以已认证账号的真实权限运行。受信任的 Python 环境也不是沙箱。DSH 工具审批约束工具调用，不能约束 Python 直接访问文件、网络或进程。修改前检查解析后的路径，验证结果时考虑软链接。
