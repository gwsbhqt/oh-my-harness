# Raycast Gemini 通过 MCP 控制 DSH 会话与任务

Raycast 里的 Gemini 负责理解目标、判断和验收，本机 DSH 模型负责实际执行。MCP 复用现有 dsh-control 本机接口，按需返回会话内容、状态与成果，不把 DSH 全套上下文塞进 Gemini。

## Raycast 接入

在支持 MCP 的客户端中注册 `dsh-control mcp` 作为 stdio 服务。客户端需要技能说明时，配置本插件的 `skills/dsh-control` 目录；界面入口和权限确认由客户端提供。

扩展通过 `ai.mcp` 声明 stdio 服务，实际命令由本机 HOME 定位 `~/.local/bin/dsh-control mcp`。它固定连接本机，不继承其他控制工具的默认远端。DSH 和该命令必须都已安装；构建产物 `lib/` 不入库，另一台机器部署后须先构建并验证。

独立 MCP 客户端也可直接以本机命令的绝对路径启动 `mcp` 子命令。命令使用进程标准输入输出通信，日志在 stderr，不增加网络端口。

## 先区分已有会话与新任务

用户给出 `session-...` 或明确指定已有 DSH 会话时，直接读取它。不要求用户提供桥任务编号或粘贴讨论。没有明确编号时，先查会话列表并核对标题、目录；标识有歧义就澄清，不猜。

仅查询会话不发消息、不换模型、不创建会话。需要在该会话继续执行时，先接入已有会话，取得桥任务编号，再用原任务工具续办。接入只建立持久对应，不复制或替换原会话，不改变原模型和上下文。只有确实需要独立新任务时才新建会话。

## 工具

| 工具 | 做什么 | 主要参数 |
|---|---|---|
| `dsh_list_workspaces` | 查询已登记的工作区 | 无 |
| `dsh_list_sessions` | 发现本机现有会话并核对目标 | 以返回的筛选参数为准 |
| `dsh_read_session` | 按会话编号读取状态和必要对话，可在运行中读取 | `session`、`turn` 或 `last`、`offset`、`max_chars` |
| `dsh_attach_session` | 接入原会话，返回后续任务工具可用的编号 | `session` |
| `dsh_create_task` | 创建独立会话并派第一份任务，默认 fast | `request_key`、`prompt`、`workspace` 或 `cwd`、`tier` |
| `dsh_read_task` | 查询派单状态和必要结果 | `task_id`、`wait_seconds`、`offset`、`max_chars` |
| `dsh_continue_task` | 在原会话继续派活，保留原模型 | `task_id`、`request_key`、`message` |
| `dsh_answer_task` | 回答 DSH 任务提出的问题 | `task_id`、`call_id`、`answers` 或 `text`/`select` |
| `dsh_cancel_task` | 按用户要求中止已关联会话的当前轮 | `task_id` |

以运行中服务返回的完整参数定义为准。读取先取最近内容，再根据需要指定轮次和翻页，使用返回的实际轮号与分页位置；不要无目的地拉全历史。默认省略思考、系统提示及原始工具日志。

## 状态与结果

任务提示要求执行者回复结论、产物绝对路径、核验结果、未完成项。相对链接应按实际工作目录补成绝对路径。

`request_key` 用于防重复：同一个 key 与相同输入只发一次，同键不同输入明确冲突。新派单生成新 key，重试沿用原 key。发送结果未知时不自动重放。

`dsh_read_task` 的等待上限为 20 秒。派单完成仍按 `wait --settled` 判定：已结束、没有排队及在跑的后台任务/子代理、持续目标不会自动续跑，并保持稳定期。`wait_seconds=0` 也不跳过这套判据。接入成功或会话当下空闲都不等于新任务执行完成。

只读已有会话时返回的是观察到的会话状态与内容，不要求先等该会话完成。它适合用户要求“看看这个讨论”“解释当前进度”等场景。

## 数据与授权

- 所有调用连接同一系统账号可访问的本机 DSH socket；本地任务对应是防重发与续办的记录，不是跨账号权限隔离。
- 用户指定已有会话后可直接读取。写入、取消或回答仍按用户实际意图；读取或接入本身不是对全局操作的授权。
- 不开放通用 `api call`、全局重启、插件或配置修改工具。
- 只向模型提供需要的用户与助手正文。Raycast 聊天、附件和研究材料不会自动搬到 DSH，必要时明确提供路径或任务摘要。
- DSH 界面的系统审批仍由用户处理；`dsh_answer_task` 只回答任务通过提问工具提出的问题。
- 现有 Raycast 权限设置保持不变。实际是否出现调用确认由 Raycast 的权限规则决定。
- MCP 不主动唤醒已经结束回复的 Gemini 聊天；长任务需沿用原任务查询结果。

## 真实验收

1. 在 Raycast 的“科研合伙人”中直接提供一个由 DSH 界面创建、未由桥派单的会话编号，确认可读出真实标题、状态和对话内容，无需手动 `@`。
2. 在运行中的会话上读取，确认及时返回；对长回复翻页，确认正文可完整取回且没有思考或原始工具负载。
3. 用专用已有会话接入并续办，核对实际会话编号与模型不变；重复派单 key 不新增消息，进程重开后仍可关联。
4. 新任务真实生成并核对文件，Gemini 取回结果。同一任务继续修改仍进入原会话。
5. 核对只读已有会话、接入与续办各自的副作用，不把接入回执或状态空闲当作完成。

## 排障

| 现象 | 说明 |
|---|---|
| 工具列表为空或进程立即退出 | 先在终端直接跑 `<command> mcp` 看 stderr；找不到 `lib/dsh-control-mcp.js` 时先在插件目录 `pnpm run build`。 |
| `dsh_unavailable` | DSH 没在运行，或 `DSH_HOME`/socket 与 DSH 不一致。 |
| `protocol-mismatch` | 运行中的 dsh-control 版本太旧，不支持 `task-outcomes` / `settled-wait`；部署新插件并重启 DSH。 |
| `store_locked` | 另一个 MCP 进程正在写任务账本，稍后重试；不会重发消息。 |
| `store_lock_stale` | 任务库锁文件属于已退出进程，但当前实现不自动删除它（避免两个进程同时清理时误删刚建好的活锁）。确认没有 MCP 进程在运行后，手动删除 `$DSH_HOME/dsh-control/mcp/.lock`；否则会一直拒绝写任务账本。 |
| `store_lock_unresolved` | 任务库锁文件存在但读不出所有者；不自动删除。确认没有 MCP 进程在运行后，手动检查并删除 `$DSH_HOME/dsh-control/mcp/.lock`。 |
| `outcome_unknown` | 发送过程中 MCP 进程断电/退出，账本里只留下“不知道发没发”；不自动重放，重建任务。 |
| Raycast 写工具要确认 | 这是 Raycast 的 AI Extensions 权限设置；按需在 Raycast 设置里调整，不影响 DSH 内部任务提问。 |
