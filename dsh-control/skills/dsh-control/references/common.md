# dsh-control 共用规则

适用于 [CLI 主说明](../SKILL.md) 与 [Python 主说明](../PYSKILL.md)。本文件的命令示意省略前缀 `dsh-control`；Python 使用同名异步函数，连字符改下划线。

## 发送回执与防重发

发送回执的 `sent`、`requestId`、`sessionId`、`since` 只证明接收，不能说任务已完成。派单默认带 `--notify`（DSH 会话里写 `self`），由插件在目标真做完后送一次通知；要当场拿结果就用 `wait --settled`。判断做没做完只认这两条路给的状态，不看目标回复里的字。先保存回执，再在后续调用继续等同一个 `since`；超时、取消或等待失败不能重新发送。发送回包丢失时可能已经送达，先查询状态和历史，不自动重发。远程发送后的 `wait` 也必须指定原机器，CLI 用相同 `-H`，Python 用相同 `host`。

新任务用 `new <工作区或绝对路径> "任务与验收标准" --tier normal`，保留实际输出的会话和起点再等待。绝对路径只开会话，不登记工作区。`chat` 将发送与等待合并，正常返回的所有等待结果保留 `receipt`；即使失败也用该回执继续等待，不再发一次。

自动维护用 `dsh-control --local new /绝对仓库路径 "任务" --if-idle --json`。`--if-idle` 是不带值的开关，不等待空闲：已有运行会话、真实排队消息或不支持重启恢复的后台任务时退出 2，错误码 `idle-required`；已有活着的重启执行进程时退出 2，错误码 `restart-pending`。这两种拒绝都不创建会话、不发送。模型选好后、创建前会复查，发送前再复查。若已经创建才被挡，退出 1，返回 `{ok:false,status:"failed",error:{code,message},data:{created:true,sessionId,workspace,since,sent:false,model}}`，保存真实 `sessionId`，不要重放 `new`。读不到重启状态且不是文件不存在、状态损坏或空闲检查不可用时明确失败，不当作空闲。普通 `new` 不加此开关，沿用正常行为。

送法按用户意图选：新独立任务默认排下一轮；纠正当前方向、补要求、回答刚才问题用 `send <会话> "修正内容" --now`；用户要求立即停下或继续有害时使用中断选项（CLI `--interrupt`，Python `interrupt=True`），会中止当前步骤并以新消息开下一轮。这类用户已授权的修正不用再问。已排队的修正先 `queue <会话>`，再只对授权的消息编号执行 `queue <会话> steer <消息编号>`；优先稳定编号，失效就重新核对，别动其他消息。

## 结果和取消

CLI 保留完整 stdout、stderr 和进程退出码，并检查 JSON 的 ok、status、error、data、receipt。以下字典附加字段只适用于 Python 封装。

返回字典保留原始 `ok`、`status`、`data`、`error`、`receipt`、`meta`，额外有 `exit_code`、完整 `stdout` 和 `stderr`。非零退出仍返回字典，不自动抛业务异常。`help`、`version`、`start` 的文本结果在 `text`；`exit_code=None` 和 `launcher-unavailable` 表示启动入口不可用。`invalid-cli-output` 是协议错误，即使退出 0 也不能当成功。

- 不带 `--settled` 的 `wait`、`chat` 只说明这一轮结束，目标可能还挂着后台任务或子代理、稍后被叫醒接着做；判断任务做完要带 `--settled` 或等 `--notify` 的通知。超时时 `data.waitingFor`、`data.blockers` 写着还没做完的原因。
- `wait`、`chat` 只有最后一轮 `completed` 且退出 0 才完成；任务出错或中止退出 1，`status` 是 `failed` 或 `aborted`，`data.turns` 保留原因与回复。
- 退出 10 表示等用户回答：原样转问题与选项，得到回答后 `answer <会话> --select "选项"`，再从原起点等。
- 退出 11 表示空闲且起点之后没有新内容。核对回执、状态与历史，不空等，不据此自动重发。
- 退出 124 表示本次等待超时，先 `status <会话>` 报真实进度，再从同一起点等，不反复发消息催。
- 退出 2 是参数、歧义或权限保护等拒绝，按错误处理；退出 69 是通信口不可用。不能把 `ok:true` 的等待输入或超时当完成。

取消 CLI 等待不撤销已送消息；Python 内核取消会传播 `asyncio.CancelledError`，异常的 `result` 保留已收输出。它只停止本地命令进程组，不撤销已送消息、不自动中止目标会话，已派出的独立后台重启仍继续。`cancel <会话>` 停的是整个会话，不是单条请求；必须有相应授权。不要把 `requestId` 当单任务取消编号。

## 模型与批量操作

`models` 看实际档位与理由，`pick normal` 只挑不改。`normal` 用于开发，`fast` 仅用于很简单的任务。以用户当前档位设置和实际额度为准；整档不可用就向用户说明重置时间，不能自行跨档。推理等级由 DSH 保留，不擅改。

会话开始后换模型会丢缓存，默认拒绝；仅当前模型额度用光时按保护条件换。发送的 `tier`、`model` 也受同样保护。强行换模型必须单独授权；用户已明确要求切换指定会话模型就属于授权，可在会话停下后使用 `--force`。`--force` 同时跳过运行中保护，等待空闲后仍要注意会话可能再次启动。

批量存档先获得范围授权，再 `sessions --ungrouped --include-blank --limit 0 --json`，核对 `meta.shown == meta.matched`。按完整 `sessionId` 逐个 `archive <完整会话编号>`，记录结果，再查同一列表。活动任务被拒时不强制中止；已存档不重复处理，未全部成功就不能报全部完成。

## 检查与重启

改插件、profile、依赖或凭据，先通过改动插件自身规定的检查，再 `doctor`。纯说明修改不要求代码全套检查或重启；若说明文件属于声明的构建输入，仍需用共用构建工具刷新产物与内容清单。doctor 先隔离检查离线层，运行中的 DSH 还必须通过通信口实际调用在线检查，任一失败都不放行。默认不请求模型；`doctor --full` 会额外联网并请求一次模型，消耗额度。未联网限制和界面验收仍列为未验证。首次缺在线 doctor 的安装例外只允许离线全过、会话空闲后挂载并立即补验，不能绕过其他失败。

有授权且确需重启时，先检查并安排：

```bash
dsh-control doctor --json
# 确认退出 0 且 ok 后，才运行：
dsh-control restart --detach --json
```

转后台后结束本轮，等完成通知再验证实际改动。不要开后台任务或 Monitor 等它。不说“已完成”，只说“已安排，实际结果待验证”。启动前会再查离线层，凭据权限可修回精确 600，其他错误拒绝启动；启动会移除 `ELECTRON_RUN_AS_NODE`。

- 改会热加载的 profile 挂载或补丁时，将待写内容放临时文件，把明确的一次性更新命令通过更新命令选项（CLI `--before`，Python `before=`）传入上述重启；所有会话中止后才写入和安装，失败就不重启，被中止的会话照样收到「继续」。直接改补丁或配置会热加载打断在跑的会话。
- 带更新命令时，如果有会话、子代理或用户排队消息未处理，或宿主后台已崩溃而状态无法确认，就明确报更新未执行、本次未重启；已中止的会话照样继续。仅剩系统后台的安静通知时不改动通知，可继续执行更新。
- 已有重启时，无更新命令只附着等待通知，不说明你的更新已安排；带 `before` 会明确拒绝。等原请求终态，再核对和安排本次更新。前置命令失败先读阶段、真实退出码、完整 stdout/stderr 日志；等待或通知失败不能重放已执行的更新命令。
- 查同一请求用 `restart-status --request-id <回执中的 UUID>` 和 `quit-check`，结合日志区分排队、执行与历史通知。查询退出 0 只代表读到了记录，必须看 `data.phase == "completed"`；旧实例退出、新实例身份不同且必要服务就绪才算重启完成，随后仍要验本次改动。
- 跨机器回执中的监听编号用 `--local restart-watch <监听编号>` 在发起机器查；远端请求状态带原机器和请求编号查询，CLI 为 `-H` 与 `--request-id`，Python 为 `host` 与 `request_id`。本机会话编号不能当远端会话编号，通知送达失败也要报告。子代理发起的跨机器重启不建完成通知（回执 `watchSkipped`），要自己按请求编号查。
- 会话内用 CLI `dsh-control restart` 或 Python `restart()` 直接重启，自动转后台并默认通知原会话。重启一律强制，没有等空闲模式，也不需要 `--force`。正常退出没走成会结束进程再拉起，不会报「退不出」。有人在跑也直接重启，不交给用户代办，被中止的会话重启后自动收到「继续」。已有执行者时只附着结果通知，不能重复执行或合并另一个前置命令。持续目标先暂停再中止，重启后恢复。
- 强制重启会停掉普通子代理和一次性后台任务。后台任务重启后在原会话用原命令、原目录自动重新拉起成持久 `monitor`，输出不推进会话（要看用 monitor_output 或 job_output 查新编号），主人闲着不叫醒、只放一条说明；查不到目录或拉起失败时，说明和你收到的重启结果都会写明，要按需自己补。子代理接不回来，上级会话会被叫醒，用 send_message 让它接着做或重新派。需要跨重启保留的开发服务器、桥接服务和监听用持久 `monitor` 托管，由重启流程暂停后接回。已有普通后台服务挡住重启、用户已授权停后恢复时，先核对实际命令、工作目录和服务用途，再精确停止这些任务并用同样命令与目录迁移到持久 `monitor`；不扩大到其他任务，不重复请求已有授权。迁移时用 `dsh-control monitor <原会话> --command <原命令> --cwd <原目录> --label <名称>` 或 Python `skills.dsh_control.monitor(原会话, command=原命令, cwd=原目录, label=名称)` 直接挂到原会话；不发消息、不请模型代开、不改成维护会话归属。这个命令只启动服务，不停止旧任务或检查服务是否可用；先确认旧任务已经停下，再启动并实测端口。重启流程自动保存、暂停和恢复这些服务，继续归原会话。通知后改用新编号，补查断开段。强制重启导致不能续回的任务要核对后按需重做。
- 通知 `accepted` 只证明已记录，`scheduled` 只证明宿主安排执行，都不证明模型回复。`recorded-unconfirmed` 和旧 `delivered` 不代表已唤醒，不能为确认而重复发送。
- 默认普通退出路线为 `apple-event`。只有明确需要时才传 CLI `--quit-via menu` 或 Python `quit_via="menu"`，先核对本机 computer-control 协议，只点唯一启用且精确命名的普通退出项；不选保留窗口、开发重启，不发全局快捷键，不自行改路线或点其他确认框；只有强制重启退不出时由 dsh-control 自己结束进程再拉起。超时不能推断权限原因；路线不同不能附着原请求，动作投递也不代表重启完成。

## 权限边界

只读状态、历史、工作区、额度、模型和接口描述可直接查。以下写入需要用户已有明确授权；已授权不重复问：中止会话、装卸插件、改配置、重启、强行换模型、存档或取消存档、重命名、分叉、换目录、暂停或清除目标、删除提醒和任意接口写入。只处理授权范围，不碰其他会话、队列、监听或他人状态。

绝不停用或卸载 dsh-control 自己，否则通信口会断。会话内需要重启时直接用 `--detach`，不交给用户在终端执行。只读模式或接口禁用时照实报告，不换调用方式绕过。

不熟悉的接口先 `api list`、`api describe <命名空间/方法>`，按真实 schema 调用；不凭记忆拼字段。凭据、终端输入、动态执行代码和账号接口在远程被禁用。CLI 按参数参考传参；Python 的参数编码见 [Python 主说明](../PYSKILL.md)。
