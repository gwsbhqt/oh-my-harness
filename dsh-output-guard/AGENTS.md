# dsh-output-guard

模型输出失控时及时停下，不把异常回复当成任务完成。

## 保护范围

- `llm/stream` 包住主代理和子代理的模型流。重复检测只看思考与正文文字，不看工具参数：代码里正常的重复行太多，套同一阈值会误伤。
- 连续空白检测覆盖思考、正文和工具参数：空格、制表符、换行及工具参数中的 JSON 空白转义连续达到 `maxBlankRun`（默认 2000）个就中止，按输出失控处理。工具参数也可能持续输出空白；重复检测会先去掉空白，所以需要单独检查。
- 单个工具调用的参数超过 `maxToolArgsChars`（默认 50000 字符）就中止，重试提示要求拆成几步写。上限用于要求模型把大块写入拆成多个步骤。
- 比较时忽略空白、`*`、下划线和反引号。默认同一个 4–160 字符单元连续重复至少 8 次、覆盖至少 64 个规范化字符时，中止当前请求；64 字门槛按实际重复段计算，不是按整段文本长度。纯符号或纯数字的结构串（如 Markdown 表格分隔行、数值列表）是正常排版，不算文字循环。
- 正常结束或达到输出上限时没有正文和工具调用，也按失败处理。
- 每回合同一步骤最多自动重试一次。重试前向会话写入一条有 `output-guard` 来源的纠错提示；不把失控原文重新交给模型。
- 第二次仍失败就交回宿主原有错误处理，不无限重试、不自动换模型、不改长期系统提示。

## 配置

条目 id 与设置命名空间都是 `output-guard`。所有选项即时影响新请求：`enabled`、`reasoningOnlyGuard`、`autoRetry`、`repeatCount`、`minCycleChars`、`maxCycleChars`、`minRepeatedChars`、`windowChars`、`maxBlankRun`、`maxToolArgsChars`。

## 验证

`test/detector.test.ts` 使用虚构短句模拟重复模式并覆盖正常文本与阈值；`test/guard.test.ts` 覆盖流式分片、上游关闭、工具参数豁免重复检测、工具参数与正文的大段空白、正常缩进代码不误伤、单次调用长度上限与分调用计数、假完成、正常透传和一次性重试；`test/session.test.ts` 用真实 Session 核对失败尝试不进入历史、纠错提示进入重试历史。

## 删除条件

宿主自己能识别文字死循环和只有思考的假完成，并提供带纠正上下文的有界重试时删除。
