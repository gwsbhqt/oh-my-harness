# dsh-history-cap

在后台截短单次发给界面的历史记录，避免某一轮包含数万条工具明细时，切到这个会话要卡几十秒。

- 宿主的历史分页按整轮切，不限条数：一轮包含很多工具记录时也可能整轮发出。本插件在 `sessionController` 实例上放同名的 `follow`、`page`、`events`，超过 `DEFAULT_MAX_HISTORY_RECORDS` 条（当前 1000）时只保留最新这么多条并设置 `hasMore: true`，界面用现有「加载更早」逐页往回读。上限太小时普通会话每次「加载更早」也只能多出少量记录，增加翻页次数。`follow` 只截第一帧快照，后续增量原样放过。不修改会话文件，不按事件类型过滤。
- 网关每次调用都从服务上现取方法（dsh-api-gateway `prepareInvocation`），所以实例上的同名方法对网页端、桌面端和远程查看都生效。原方法总从原型取，热加载不叠层。宿主内部目前没有别的代码调用这三个方法；新增调用前先确认能接受被截短。
- 上游给分页增加原始记录数上限后，删除本插件。
- 修改后运行 `pnpm run check`。测试照网关的调用方式取方法，覆盖虚构的一轮 2.4 万条的打开、连续翻页无缺口、切走时关闭原始流、卸装恢复。
- 改后台插件要重启 DSH 才生效。实际启用后在真实实例里从普通会话切到超大会话，量页面长任务时长和收到的快照大小，确认「加载更早」可用。只看到「加载更早」不算证据：有更早轮次的会话本来就会显示它。
