# dsh-guard

两套模型护栏合在一个包里，作为两个独立条目加载：**输出护栏**拦住失控的模型输出，**目标护栏**让模型自己管目标、知道什么时候该收口。它们钩子不同、命名空间不同、开关各自独立。

## 条目与导出

`cordis.patch.yml` 插入两个条目，指向包的两个不同导出，避免一个条目把两套钩子都装一遍：

| 条目 id（= 设置命名空间） | 模块 | 作用 |
| --- | --- | --- |
| `output-guard` | `.`（`lib/index.js`） | 输出护栏 |
| `goal-guard` | `./goal-guard`（`lib/goal-guard.js`） | 目标护栏 |

两个条目可分别开关，互不影响。两个模块各导出自己的 `name`（`dsh-guard` 与 `dsh-guard/goal-guard`），只用于加载诊断；设置命名空间是条目 id，不是导出名。

## 输出护栏

- `llm/stream` 包住主代理和子代理的模型流。重复检测只看思考与正文文字，不看工具参数：代码里正常的重复行太多，套同一阈值会误伤。
- 连续空白检测覆盖思考、正文和工具参数：空格、制表符、换行及工具参数中的 JSON 空白转义连续达到 `maxBlankRun`（默认 2000）个就中止，按输出失控处理。工具参数也可能持续输出空白；重复检测会先去掉空白，所以需要单独检查。
- 单个工具调用的参数超过 `maxToolArgsChars`（默认 50000 字符）就中止，重试提示要求拆成几步写。
- 比较时忽略空白、`*`、下划线和反引号。默认同一个 4–160 字符单元连续重复至少 8 次、覆盖至少 64 个规范化字符时中止；64 字门槛按实际重复段计算，不是按整段文本长度。纯符号或纯数字的结构串（如 Markdown 表格分隔行、数值列表）是正常排版，不算文字循环。
- 正常结束或达到输出上限时没有正文和工具调用，也按失败处理。
- 每回合同一步骤最多自动重试一次，重试前写入一条标有 `dsh-guard` 来源的纠错提示；不把失控原文重新交给模型。第二次仍失败就交回宿主原有错误处理，不无限重试、不自动换模型、不改长期系统提示。

## 目标护栏

- **工具包装**（`src/goal/tool-wrap.ts`）：在每个 agent 自己的工具层注册同名 `update_goal`，遮蔽预设层的版本（同 dsh-grep-scope 的 scoped 遮蔽）。`pause` 不走宿主的暂停（宿主暂停只有用户能恢复，模型暂停后目标会无声卡住），改记成代码 `model-paused` 的 blocked，模型之后能自己 resume；`edit`、`complete`、`blocked`、`resume` 先交给宿主，宿主只因「这一轮没有权限」拒绝时顶层会话直接调目标服务补上，其它拒绝（轮数门槛、版本过期）原样抛出。用户亲手点的暂停不恢复；子代理不补位。
- **收口规则**（`src/goal/wrap-up.ts`）：在有 `update_goal` 的会话里按 `TOOL_GOAL` 的位置加一段固定系统提示，告诉模型什么时候 complete、pause、edit，别把「等别人、等用户」当成剩余工作。文字固定，只按会话有没有 `update_goal` 出或不出，不影响前缀缓存。
- **空转刹车**（`src/goal/stall.ts`）：订阅 `session/event` 按记录自己数，不经模型。续跑轮（来源 `goal`、round > 0）里没有一次工具调用成功（全失败或一次没调）算空转；有一次成功或用户亲自发消息清零，其他通知轮不改计数，被中止的轮不算。连续 `stallRounds` 轮空转就把顶层会话的目标记成代码 `no-progress` 的 blocked，原因里带最后一条工具报错。停下的那一刻不依赖模型能不能调工具。

## 配置

每个条目 id 与设置命名空间一致，都是各自 id。所有选项即时生效：

- `output-guard`：`enabled`、`reasoningOnlyGuard`、`autoRetry`、`repeatCount`、`minCycleChars`、`maxCycleChars`、`minRepeatedChars`、`windowChars`、`maxBlankRun`、`maxToolArgsChars`。
- `goal-guard`：`enabled`（总开关，关掉后收口规则、工具包装、空转刹车一起停用；关掉期间不累计空转，重开后从零开始）、`modelControl`（模型暂停改成可恢复的停止、没权限的轮次补位）、`wrapUpGuidance`（有目标工具的会话加收口规则）、`stallRounds`（续跑连续几轮没一次工具调用成功就停下目标，0 = 不管）。

## 验证

- `test/detector.test.ts`：用虚构短句模拟重复模式，覆盖正常文本与阈值。
- `test/guard.test.ts`：覆盖流式分片、上游关闭、工具参数豁免重复检测、工具参数与正文的大段空白、正常缩进代码不误伤、单次调用长度上限与分调用计数、假完成、正常透传和一次性重试。
- `test/session.test.ts`：用真实 Session 核对失败尝试不进入历史、纠错提示进入重试历史。
- `test/goal-guard.test.ts`：工具包装单测（暂停记成可恢复的停止、没权限时补位、其他拒绝原样抛、子代理不补位、开关、字段透传、收口规则按会话出或不出、空转计数）；用假原工具和假目标服务，不起宿主。
- `test/root-agent.test.ts`：顶层会话按会话头识别，不依赖宿主某版本的 roots 接口（含 null / undefined 输入）。
- `test/load.test.ts`：用真实 cordis 加载两个入口模块（源码 import 后按插件 apply，分别对应 `dsh-guard` 与 `dsh-guard/goal-guard`），核对是两个不同模块、各 apply 一次、只装一次收口规则与一次 `update_goal` 遮蔽，卸载后工具包装被撤、监听不再重装。编译产物的两个条目由重启后的真实 DSH 验证。

真实 DSH 里另需验：目标服务能从 `agent.ctx.get('goals')` 取到；两个条目都加载且设置卡片可分别开关。

## 公开边界

本包在公开仓库，只用虚构样例。示例和注释不写真实会话编号、个人机器和故障经历；需要说明边界时用通用描述。

## 删除条件

- 输出护栏：宿主自己能识别文字死循环和只有思考的假完成，并提供带纠正上下文的有界重试时删除。
- 目标护栏的工具包装：宿主给模型可恢复的暂停、并在非用户非续跑的轮也放行 edit / complete 时删除，保留收口规则和空转刹车。
