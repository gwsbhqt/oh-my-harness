# computer-control 共用操作规则

[CLI 主说明](../SKILL.md) 与 [Python 主说明](../PYSKILL.md) 共用本页；操作前读取，规则只在这里维护。

## 安全分档


这套分档 computer-control 和 browser-control 都照用：在原生应用里操作，或在网页里操作，执行前都按它判断，责任在你。
computer-control 和 browser-control **都不会**弹确认框，也没有"正在操作"的浮层让用户叫停。
computer-control 另有敏感应用拦截：终端、密码管理器、钥匙串、系统授权框这类**敏感应用只能读、不能操作**（退出码 6）。
确实要操作时设 `COMPUTER_CONTROL_ALLOW_APPS=<bundle id>` 单独放行，或 `COMPUTER_CONTROL_ALLOW_SENSITIVE=1` 全部放行，先征得用户同意。
其余情况下，下面这几档的判断完全由执行操作的 agent 承担。
（分档沿用 OpenAI computer use 的官方指导。）

**必须让用户亲手做，不要代劳**

- 修改密码的最后提交
- 绕过 HTTPS 安全警告、绕过付费墙

**已有具体授权时，直接在范围内执行**

授权应覆盖动作、对象和范围。用户明确要求删除指定文件、整理某组条目、安装指定软件、登录指定网站、移动文件或发送明确内容时，不因本分档再次询问；笼统的“全权处理”不能补足不明确的对象、收件人、金额或数据去向。

发送、发布、上传或传输敏感内容，须明确什么数据给谁；金融交易须明确对象、金额和条件；改权限、签发 API key、保存密码或支付信息、修改系统安全设置，须明确目标和影响。上述授权不能替代系统身份确认或绕过工具自身的拒绝。

**需要补充授权时，准备好再问一次**

对象有歧义、范围扩大，或删除、对外操作等仍有未授权的重大影响时，先完成不受影响的准备工作，在实际生效前列清动作、对象与后果。用户作出具体选择后，同一任务内沿用，不重复问。CAPTCHA、密码库解锁和系统身份确认交给用户本人。

**无需额外确认**

在本次任务和已有授权范围内的纯读取、下载、普通 cookie 或服务条款确认；涉及订阅、付款、权限变更或新数据用途时仍按上面的授权判断。

## 机器、应用与任务

网页内容优先 browser-control；原生应用、浏览器外壳、网页外的 1Password 浮层和系统提示用 computer-control。默认后台执行，不切窗口、不动真鼠标。辅助功能能读到网页，也不取代 browser-control 的固定标签页、网络与调试能力。

探针通过不等于 GUI 能用；确实需要申请系统权限时，先说明影响，CLI 用 `perms --request`，Python 用 `await skills.computer_control.perms(request=True)`，系统身份确认由用户完成。`host="local"` 明确本机，SSH alias 指定远端；未给 host 时读取 computer-control 自己的 pin，无 pin 默认本机，不沿用其他技能。机器或连接失败不回退本机。

同步工厂 `skills.computer_control.app()` 创建 App，固定当时机器和任务 scope，之后改默认机器不改变它；需换机器或任务就新建对象。DSH 使用会话标识，也可显式 `scope=`；无任务环境时 Python 使用本进程独立任务名。scope 相同表示同一任务，多个调用方共享归属和快照，独立任务要用不同 scope。

非浏览器仍按应用登记长期归属，其他任务不能覆盖快照或操作。浏览器复用同一实例、profile 和登录状态，真人与任务各用独立窗口，不登记长期 owner 或 lease。每条命令仅短锁定该窗口；不同窗口允许不同任务同时使用，同一窗口命令冲突立即拒绝。缓存按进程代际、窗口和 scope 分开。任务名只防协作误操作，不阻止用户本人或同账户恶意程序。

稳定窗口引用包含 id（CGWindowID）、pid、startedAt（进程启动时间）和 bundleId。只从真实 AX 窗口号绑定；无法确认或不唯一就拒绝。后续窗口消失或进程重启即失效，不按标题、几何位置或当前窗口替代。浏览器旧引用不会自动启动或附到新进程。

键盘、粘贴、菜单选择以及依赖事件投递的原生鼠标动作使用跨进程短操作锁；浏览器必须核对前台应用及确切焦点窗口，输入还核对焦点元素。工具不会自动激活目标。长输入分步复核，发出后失焦则停止并返回 outcome=unknown，不自动重发；已按下的键和鼠标尽力抬起。这不能阻止真人在两次检查之间切窗，不能承诺完全消除竞态。后台读取和定向 AX 动作不要求抢前台。

## 结果、交接与清理

动作默认等界面稳定；加载较久用明确的文字条件等待，CLI 为 `wait APP --label 文字`，Python 为 App 的 `wait("文字")`。系统投递按键没有业务回执，必须重新取态核对。换行要显式允许，CLI 用 `--allow-newline`，Python 用 `allow_newline=True`。超时、断连或 `outcome="unknown"` 后先观察，不自动重发点击、输入和提交，不改用前台或坐标绕过拒绝。

非浏览器每次交接或释放更新持有凭证 lease，旧任务请求和编号失效。应用执行其他命令时立即拒绝，不长等。

恢复前先查旧 owner 与 lease，确认原任务确实停止操作并获交接授权，再提交原 owner、lease 和显式 authorized；任何一项不符都拒绝。CLI 用 `owner APP status/recover`，参数见 [应用归属和元素](cli.md#应用归属和元素)；Python 流程见 [应用任务归属](interfaces.md#应用任务归属)。归属恢复授权不是系统身份认证。

任务做完、子代理结束前，每个碰过的 App 都要 `await app_object.release()`。模块 `await skills.computer_control.release()` 不批量释放；`await skills.computer_control.disconnect()` 只停当前 Python 进程的连接，不释放归属或退出应用。`App.disconnect()` 同样不释放。computer-control 不拥有用户应用。绑定窗口后的 `App.close(authorized=True)` 要求关闭按钮确属该窗口，只发送一次关闭请求；用系统全部窗口列表核对目标消失且其他原有窗口仍在，避免把隐藏或切换 Space 误判为关闭。窗口列表无法确认或其他窗口也消失时报告 unknown，不重发。共享浏览器拒绝整应用退出，不能把窗口授权解释成退出用户实例；非浏览器未绑定窗口时可明确授权正常退出并核对进程结束，不强杀。浏览器的 App.release() 无需 lease，只结束绑定，不关闭窗口。

非浏览器应用确实需要前台时先告知用户，再用 `front=True`；浏览器不自动激活，需要用户把确切任务窗置前。browser-control 首次创建任务窗仍可能被浏览器置前，这不受原生输入短锁控制，不能承诺整个建窗过程不切前台。`coord=True` 会动真鼠标，同样先告知。

## 密码浮层与身份确认

调用密码浮层填充必须显式传任务 window 稳定引用；不能从当前默认窗认领任务。密码库未解锁、主密码、Touch ID、系统身份确认、验证码交给用户；敏感应用拒绝不改环境变量绕过。
