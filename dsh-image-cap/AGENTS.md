# dsh-image-cap

限制发给模型的图片长边和单次请求的图片数，补足宿主只按面积或字节处理时的空缺。插件不处理像素，不替代 DSH 的编码、压缩、缓存和适配器预算。

## 维护不变式

- 长边：只在宿主计算的请求目标超过上限时，用宿主 `longEdgeDimensions()` 得到更小目标，再交给 `attachments.readImageRequest()`。不能放宽已有的面积或字节限制。
- 张数：在 `LlmRuntime.adapterStream()` 交给适配器之前，仅对 agent-loop 请求投影。这个入口同时覆盖 `llm.stream()` 与 `preparedCall.stream()`，避免修改日志或触发请求重建不变式。
- 超限时省略最老图片，按 `imageCountQuantum` 向上取整。用宿主 `offloaded: true` 和 `projectOffloadedImages()` 生成附带附件信息的文字占位；不自行拼造附件路径，不修改原消息。
- 只覆盖经过这些宿主服务的请求。外部工具自己发出的网络请求不经过本插件。
- 包装方法安装前捕获原实现。真实 Cordis 服务经代理读取方法时可能每次返回新包装，不能靠直接比较读取到的方法判断所有权。使用共用 `installMethodPatch()`；卸载只撤自己的一层，保留别人的层，并支持乱序热重载。
- 配置读取、投影或占位符处理出错时原请求照常交给宿主，并记录警告。宿主结构变化可能使限制失效，升级后必须跑契约测试。

## 配置

条目 id 为 `image-cap`。四项均为 volatile，设置卡修改后作用于后续请求，无需重挂。schema 默认值、随包 config 和用户 profile 覆盖按顺序叠加。

| 选项 | schema 默认 | 随包值 | 说明 |
| --- | --- | --- | --- |
| `maxLongEdge` | `2000` | `2000` | 模型请求中图片的长边上限 |
| `maxImagesPerRequest` | `30` | `16` | 单次请求最多保留多少张图；较低的随包值减少重复传输的图片数，不代表所有服务商的硬上限 |
| `imageCountQuantum` | `8` | `8` | 超限时省略的步长，较大的步长使同一段历史前缀保持更久 |
| `providerMaxImages` | `{}` | `{}` | 按实际 provider id 覆盖张数上限，未配置的用全局值 |

虚构的 4800×800 输入在长边 2000 时目标为 2000×333，仍由宿主实际缩图。测试里显式配置上限 30、步长 8 时，31 张和 38 张都省略最老 8 张，39 张省略最老 16 张。这是算法用例，不是线上服务验收或个人用量。

## 验证

运行 `pnpm run check`，包含类型检查、构建和测试。尺寸与图片引用全部为虚构夹具；长边测试运行真实宿主计算函数，张数测试运行真实宿主占位投影。真实 Cordis 服务测试覆盖代理方法、卸载和重载；真实 LLM 运行时搭配记录型适配器覆盖两条公开入口，不请求外部模型。

所有设置、安装步骤、取舍和许可证见 [README.md](README.md)。宿主提供等效的长边及张数策略后再考虑移除。不要把某一服务商的限制或个人排障记录当成所有 provider 的规则。
