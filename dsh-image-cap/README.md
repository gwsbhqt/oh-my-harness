# dsh-image-cap

[← 返回首页](../README.md#由哪几块组成) · [教程](../docs/dsh-image-cap.md)

**一句话：** 限制发给模型的图片尺寸和张数。

给 DeepSeek Harness（DSH）发往模型的图片设置长边上限和张数额度。它补充宿主按面积、字节、编码和缓存处理图片的策略。本插件不直接处理像素，也不引入原生图片依赖。

## 使用条件和安装

需要兼容的 DeepSeek Harness（DSH），提供附件服务和 LLM 适配器运行环境。还需要 Node.js `^22.19.0 || >=24.0.0` 和 pnpm。包清单记录已测试的宿主依赖；当前测试使用 DSH 0.2.2-rc.1。保留所在仓库中与插件相邻的共用 `tooling/` 目录。不能只拿这个源码目录单独构建。

在本插件目录执行：

```sh
pnpm install --frozen-lockfile
pnpm run check
```

在 DSH profile 的包清单中合入链接依赖和组合包：

```json
{
  "dependencies": {
    "dsh-image-cap": "link:../../path/to/oh-my-harness/dsh-image-cap"
  },
  "dsh": {
    "profile": {
      "bundles": ["dsh-image-cap"]
    }
  }
}
```

把示例链接改成相对于你的 profile 目录的路径。使用 DSH 支持的 pnpm 安装 profile 依赖。提供启动检查器时先校验 profile，再重启 DSH。组合包已经登记条目，不要重复插入。

## 行为和与 DSH 的分工

如果请求中的图片目标尺寸超过 `maxLongEdge`，插件调用宿主的 `longEdgeDimensions()` 算出更小的目标，再交给宿主附件服务。实际缩图和编码仍由 DSH 完成。已经更小的目标和原有字节额度都保留。虚构的 4800×800 图片在长边上限 2000 像素时，目标为 2000×333。

对于助手循环中的请求，在调用适配器之前统计保留的图片块。如果张数超过对应服务商配置的额度，就把最早的图片标为已移出当前请求，再使用 DSH 自己的处理生成带附件信息的文字占位。原始会话消息和附件都不变。被省略的图片不会进入这次模型请求；再次查看需要使用宿主的附件读取工具。

按批次省略图片，避免每加一张就改变历史前缀。明确设置张数上限为 30、批次为 8 时，虚构请求中有 31 张就省略最早的 8 张、保留 23 张；38 张仍省略这 8 张，39 张则省略 16 张。较大的批次可能多省略一些图片，但历史前缀保持稳定更久。批次为 1 时省略最少，代价是前缀变化更频繁。

适配器的接入点覆盖助手循环请求中的 `llm.stream()` 和 `preparedCall.stream()`。不限制外部工具自己发起的网络请求，不替代适配器的字节上限，也不改变非助手请求的图片张数。读取设置或处理图片时出错，会警告并把原请求交给宿主。宿主内部方法变化可能让接入失效，约定测试会核对这些位置。

这是可配置的策略，不是所有服务商统一的上限，也不保证某个服务商会接受请求。按实际服务商和质量需要选额度。长边越小，细节越少；张数越少，每次请求中保留的较早图片也越少。

## 配置

在 profile 补丁里覆盖现有条目，或使用 DSH 网页界面中的设置卡片：

```yaml
- id: image-cap
  config:
    maxLongEdge: 2000
    maxImagesPerRequest: 16
    imageCountQuantum: 8
    providerMaxImages: {}
```

四个字段均即时生效，作用于后续调用，无需重新挂载。随包张数额度有意低于 schema 默认值；文档不会改变现有默认值。

| 设置 | schema 默认值 | 随包值 | 含义 |
| --- | --- | --- | --- |
| `maxLongEdge` | `2000` | `2000` | 目标长边的最大像素数，最小为 1。通过附件服务生效。 |
| `maxImagesPerRequest` | `30` | `16` | 全局请求图片张数额度，最小为 1。较低的随包值减少重复传图。 |
| `imageCountQuantum` | `8` | `8` | 每批省略多少张，最小为 1。 |
| `providerMaxImages` | `{}` | `{}` | 按实际服务商 ID 配置张数额度，各值最小为 1。未配置的 ID 使用全局张数额度。 |

profile 覆盖值优先于组合包。禁用整个插件时，在 `id: image-cap` 上设 `disabled: true`。代码改动需要重新构建并重启 DSH。

## 开发和验证

```sh
pnpm run typecheck
pnpm run build
pnpm run test
# All three:
pnpm run check
```

测试中的尺寸、服务商 ID 和附件引用均为虚构。测试调用宿主真实的尺寸计算和图片省略处理函数。真实 Cordis 服务用来检查包装方法的归属、原型方法、热加载和卸载。接到真实 LLM 运行环境上的记录型适配器核对两个请求入口，不调用外部模型。这些检查不测量真实服务商限制、上传节省或界面渲染。

源码依赖宿主内部方法的形状。升级 DSH 后要跑约定测试。宿主策略提供两种等效限制时，再移除本插件。
